4 / 38
Notes
  • How do we find the similar sentences. In each study we use one measure, cosine similarity over sentence embeddings, sent2vec in the NMT work and MiniLM in the LLM work, with a FAISS index and a threshold of 0.5. FAISS is the library that stores the memory vectors and finds the closest ones to the query quickly, so a memory of a million sentences is searched in a fraction of a second. It matches meaning, so paraphrases and reorderings count, and it retrieves the most useful examples most of the time.
  • The alternatives fit other situations. Cross-lingual embeddings such as LaBSE or SONAR when the memory is monolingual, which is your cross-lingual fuzzy-matching work. BM25 for speed on very large pools, which is what the RL selector shortlists with, together with SONAR. Edit distance when the memory is near-duplicate and the match percentage has to be interpretable. And character-set Jaccard when no encoder covers the language, which is what we did for the Sorbian-source directions at WMT.

Notes, step 4 of 4
  • How this is done in practice. Every memory source is encoded once with a multilingual MiniLM sentence encoder into a 384-dimensional vector, sent2vec in the NMT work, and the vectors go into a FAISS index. FAISS in simple terms. It is a library that stores all the memory vectors and finds the ones closest to a new vector fast. Comparing the query with every memory sentence one by one is slow once the memory holds a million sentences. FAISS organises the vectors so that the nearest ones come back in a fraction of that time, like an index at the back of a book instead of reading every page. At translation time the source is encoded the same way and FAISS returns its nearest neighbours by cosine. We keep the matches with a score of at least 0.5 and drop exact copies of the source. The NMT system gets the target of the best match after the source with a separator. An LLM gets the top k pairs as examples, most similar first.

Notes
  • We then carried the recipe to LLMs, with Els Lefever and Arda. First the configuration, on legal English to Ukrainian with 50 thousand pairs. Zero-shot Mistral-7B is far behind NMT. Fuzzy matches in the prompt alone bring it level with NFR.   • The two parts are complementary. Fine-tuning lifts the lexical metrics, the in-context examples lift COMET. At this data size the LLM beats NFR by up to 11.62 BLEU across directions, while fuzzy matches do not yet help NMT, which needs more data for that.

[Moerman, Tezcan & Macken 2026]

Notes
  • First the project our third study comes from. MaTIAS stands for machine translation to inform asylum seekers. In Belgian reception centres the staff write one message, for example about an appointment or a change in the rules, and the platform translates it into the languages of the residents. Ghent University runs the project with Fedasil, the Belgian reception agency.
  • Why it is needed. The residents speak many languages, and several of them have little data. The ten largest groups seeking asylum in Belgium in 2024 spoke languages from Arabic and Tigrinya to Pashto and Somali. An earlier human evaluation in the project judged the Tigrinya output too poor to send to residents.
  • Our part. The project only has a small memory of translated messages, 358 sentences. We asked whether fuzzy matches from such a tiny memory still help, with LLMs and with the adaptive NMT system the platform uses, across 14 languages. The next slides show the platform and then what we did.
